# 飞书接入（本轮暂缓）

> **当前状态：数据只保存本地，本 Skill 不发起任何网络请求，也没有同步代码。**
> 按 Chris 的安排，飞书连接由他本人负责；到需要连接时，告诉助手「我要接飞书」，助手会**一步一步带做**，每一步给可复制的操作与验证点。

## 触发时需要准备什么

| 项 | 从哪来 | 备注 |
|---|---|---|
| 企业自建应用 App ID / App Secret | 飞书开放平台 → 创建企业自建应用 | 只放环境变量，绝不写进配置文件或本包 |
| 多维表格 `app_token` | 目标多维表格 URL | 建议**每位同事一张表**，不要共用一张 |
| 数据表 `table_id` | 多维表格 → 数据表设置 | 工资表、账单表各一张 |
| 应用权限 | 开放平台 → 权限管理 | 仅需多维表格读写相关权限 |
| 应用发布 / 可用范围 | 开放平台 → 应用发布 | 需要管理员审批时才找管理员 |

## 届时的分步流程（助手带做，不要现在自己猜）

1. 创建企业自建应用，拿到 App ID / App Secret。
2. 用 `tenant_access_token` 调一次只读接口，验证凭据与网络连通。
3. 新建多维表格，按下方字段建两张数据表。
4. 给应用授权，确认能读写目标表（先写 1 条测试记录再删）。
5. 把本地 `data/` 的两张 CSV 映射成记录，先 `--dry-run` 打印载荷核对。
6. 首次真实同步，逐条核对月份、金额、来源是否一致。
7. 定好更新频率与去重键（建议 `来源 + 月份 + 原始文件`）。

## 建议的字段映射（供届时参考，本轮不实现）

**工资表**：期间 / 税前 / 养老 / 医疗 / 失业 / 公积金 / 社保合计 / 个税 / 税后
**账单表**：来源 / 月份 / 应还金额 / 最低还款额 / 账单周期 / 用电量 / 状态 / 原始文件

看板「导出数据 JSON」得到的 `看板数据.json` 已包含 `salary`、`bills`、`monthly`、`sources` 四组结构化数据，可直接作为同步输入。

## 隐私红线（接飞书时同样适用）

- 🚫 **不要把 Chris 的真实收支放进同事能访问的共享表**。每位同事应只上传自己的数据、只访问自己的表。
- 🚫 不要把 `config.json`、`state.json`、真实账单原件、真实看板 HTML 上传。
- ✅ 验证同步流程时统一用 dummy 数据，确认无误后再换真实数据。
- ✅ 权限按人隔离，宁可多建一张表，也不要图省事共用。

## 为什么不把飞书逻辑写进 Skill

飞书凭据属于**每个使用者自己的企业环境**，写死在包里既不能用也不安全；而且本轮明确要求「数据先保存本地」。等连接条件具备时，由助手按上面的步骤现场指导，比预置一段跑不通的代码更可靠。
