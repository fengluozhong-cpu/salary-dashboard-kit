# 按自己的账单改参数（核心）

**只改 `profiles/sources.json`，不用改 Python。** 改完重跑 `python bill_parser.py` 再 `python dashboard.py`。

## 文件结构

```json
{
  "sources": [
    {
      "name": "demo_card",
      "label": "示例信用卡 A",
      "save_subdir": "bills/demo_card",
      "extensions": [".html", ".pdf"],
      "parser": {
        "type": "generic",
        "patterns": {
          "amount": "本期应还金额[^0-9]{0,40}([0-9,]+\\.[0-9]{2})",
          "min_payment": "最低还款额[^0-9]{0,40}([0-9,]+\\.[0-9]{2})",
          "cycle": "(账单周期[^\\s]{0,60})"
        }
      }
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✅ | 内部标识，英文/数字，别改得太随意 |
| `label` | ✅ | 看板上显示的来源名，写你习惯的中文名 |
| `save_subdir` | ✅ | `data/bills/` 下的子目录；**最后一段必须与磁盘目录名完全一致** |
| `extensions` | — | 允许解析的扩展名，目前支持 `.html` / `.pdf` |
| `parser.type` | ✅ | `generic`（配置正则）或 `builtin`（用内置解析器） |
| `parser.patterns` | generic 必填 | 每个字段一条正则 |

## patterns 支持哪些字段

| key | 提取什么 | 写入 CSV 哪一列 |
|---|---|---|
| `amount` | 应还金额 / 价税合计 | 应还金额（会去千分位转 float） |
| `min_payment` | 最低还款额 | 最低还款额 |
| `cycle` | 账单周期 | 账单周期 |
| `usage` | 用电量等数值 | 用电量 |
| `status` | 自定义状态文本 | 状态（不给则自动填 `已提取` 或 `未匹配到金额`） |
| `period` | 自定义月份 | 月份（不给则从文件名 `YYYY-MM` 推断） |

> JSON 里正则的反斜杠要写两次（`\\.` 表示正则的 `\.`）。

## 三条规则

1. **用第 1 个捕获组包住要取的值**，其余文字只是定位锚点。
2. `[^0-9]{0,40}` 这种写法用来跳过「：¥（小写）」等中间字符，比写死标签更抗排版变化。
3. 每条正则独立，匹配不到就留空，**不会中断整批解析**；只是该账单 `状态` 会标成「未匹配到金额」。

## 接入一家新银行的完整例子

假设你的账单里有这么一行：

```
本期应还款总额   RMB 3,408.60 元    最低还款额 RMB 340.86 元
```

**第 1 步**：在 `profiles/sources.json` 的 `sources` 里加一段：

```json
{
  "name": "my_card",
  "label": "我的信用卡",
  "save_subdir": "bills/my_card",
  "extensions": [".html", ".pdf"],
  "parser": {
    "type": "generic",
    "patterns": {
      "amount": "本期应还款总额[^0-9]{0,40}([0-9,]+\\.[0-9]{2})",
      "min_payment": "最低还款额[^0-9]{0,40}([0-9,]+\\.[0-9]{2})"
    }
  }
}
```

**第 2 步**：建目录 `data/bills/my_card/`，把账单放进去，文件名带月份，如 `2026-01.html`。

**第 3 步**：先单独验正则，确认能取到值：

```bash
python -c "import re,generic_parser,json; p=json.load(open('profiles/sources.json',encoding='utf-8'))['sources'][-1]; t=generic_parser._read_text('data/bills/my_card/2026-01.html'); print(re.search(p['parser']['patterns']['amount'],t).group(1))"
```

**第 4 步**：`python bill_parser.py` → `python dashboard.py`。看板「支出」页会多出「我的信用卡」一列。

## 月份识别

优先从文件名取 `YYYY-MM` / `YYYYMM`（如 `2026-01.html`、`202601.pdf`）；文件名没有就从正文找 `2026年1月` 之类；都没有则写 `unknown`。需要特殊格式时加 `period` 正则覆盖。

## 内置解析器

若账单恰好与既有格式一致，可用 `{"type": "builtin", "key": "cmb"}`。可用 key：`cmb` / `cgb` / `citic` / `cib` / `electricity`。**内置解析器针对特定机构的历史排版，换一家银行大概率不适用，建议优先用 `generic`。**

## 常见坑

| 坑 | 处理 |
|---|---|
| 目录名与 `save_subdir` 末段不一致 | 该目录会被直接跳过，且不报错 |
| 账单是 GBK 编码 | 解析器已按 meta charset / gb18030 回退，无需处理 |
| HTML 里金额写成 `&yen;` | 已做实体反转义，正则里写 `[^0-9]{0,40}` 即可 |
| PDF 提取不到文字 | 需装 `PyMuPDF`；扫描件（图片型）取不到，需人工补 CSV |
| 同一来源同月多份文件 | 金额会累加，注意别把正文和附件重复放进去 |
