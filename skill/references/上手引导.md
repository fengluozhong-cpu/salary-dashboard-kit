# 新用户上手引导（详细版）

`SKILL.md` 的第 0–6 步在此展开：每步的操作、命令、验证点与失败处理，编号与 `SKILL.md` 完全一致。零网络声明见 `SKILL.md`「红线」唯一一处；可执行核验见本文件「隐私核验」。

## 引导原则

- 先查状态，再开口：`python setup_check.py` 会告诉你当前缺什么。
- 一次只推进一个数据源，验证通过再接下一个。
- 每接完一个问一句「还有别的要接吗？」，直到用户说没有。
- 真实邮箱地址、授权码、密码由你自己在本地配置，不要把值发给助手或贴进聊天。
- 任一步失败按 `SKILL.md`「失败分支」处理；仍失败则停下并报告用户，不进入下一步。

## 顺序总览（唯一编号口径，与 SKILL.md 同号）

| 步 | 做什么 | 完成标志 | 决策点 / 失败分支 |
|---|---|---|---|
| 0 | 跑 `setup_check.py` 查状态 | 拿到当前缺口清单 | 失败分支 1 |
| 1 | 问用途：只看演示 / 接自己的数据 | 用户选定 | 🔴 CHECKPOINT ① |
| 2 | 选数据来源：A/B/C（可多选） | 列出要接的源 | 🔴 CHECKPOINT ② |
| 3 | 逐个接入，每个都验证（含多工作区） | 该源数据出现在 `data/` | 🔴 CHECKPOINT ④、失败分支 2 / 3 |
| 4 | 多份时合并 `bills_parsed.csv` | 一张合并后的 8 列 CSV | 失败分支 4 |
| 5 | `python dashboard.py` 生成并量化核对 | 退出码 0、月份数一致 | 失败分支 5 |
| 6 | 删除 `data/IS_DUMMY.txt` 后重生成 | 看板不再有 dummy 水印 | 🔴 CHECKPOINT ③ |

---

## 第 0 步 · 查状态

```bash
python setup_check.py
python setup_check.py --json    # 供 Agent 解析
```

输出会显示：是否仍是 dummy、两张 CSV 是否存在及行数、有几个账单来源目录、是否已配邮箱凭据（只显示「是/否」，不显示值）、看板是否已生成，并给出按优先级排序的下一步建议。

❌ 退出码非 0 / 无输出 / `--json` 不是合法 JSON → 按 `SKILL.md`「失败分支 1」修复；仍失败则停下并报告用户，不进入第 1 步。

## 第 1 步 · 问用途

只问一个问题：「你想先看演示效果，还是直接接入自己的数据？」

🔴 CHECKPOINT：等待用户明确回答/确认后方可继续

停留动作：只输出这一句；不执行 `python dashboard.py`、不进第 2 步；用户未回答就原地等待，不替用户选。

- 只看演示 → `python dashboard.py` → 打开 `data/收支统一看板_DEMO.html` → 引导结束。
- 接自己的数据 → 第 2 步。

## 第 2 步 · 选数据来源（可多选）

🔴 CHECKPOINT：等待用户明确回答/确认后方可继续

停留动作：只列出下表 A/B/C 三个选项并等待用户勾选；不预填来源、不开始第 3 步接入；用户未回答就原地等待。

| 选项 | 适合 | 凭据（硬取值） | 上手成本 |
|---|---|---|---|
| **A 本地 CSV / 账单文件** | 已有银行导出、电子账单 HTML/PDF、手工记账 | 无 | 最低 |
| **B 邮箱 IMAP** | 想让工资条和账单自动进目录 | IMAP 授权码：用户本地设 `SALARY_EMAIL` / `SALARY_IMAP_AUTH_CODE`，本包不代填 | 中 |
| **C 其他数据源** | 支付宝 / 微信 / 银行流水 / 房租 / 物业费等 | 无；前提是把来源在本地导出成 CSV，本包不处理登录 / 授权 | 中 |

> 用户说「有多个邮箱」「还有其他数据源也一起接」时，记成一张清单，按第 3 步**一个一个接**，不要并行铺开；单进程原生多邮箱账号不支持，多邮箱走 3.4 多工作区。

## 第 3 步 · 逐源接入

### 3.1 A · 本地 CSV / 账单文件（推荐先走这条）

1. 工资：`data/工资年度汇总.csv`，10 列，格式见 `references/数据格式.md`。
2. 账单文件：按 `profiles/sources.json` 的 `save_subdir` 建目录（如 `data/bills/my_card/`），文件名带月份 `2026-01.html`。
3. 新机构改 `profiles/sources.json` 的正则，步骤见 `references/配置指南.md`。
4. 运行 `python bill_parser.py` → 产出 `data/bills_parsed.csv`（8 列）。
5. **量化验证**：数据行数 > 0，金额、月份、来源名符合预期：
   ```bash
   python -c "import csv;r=list(csv.DictReader(open('data/bills_parsed.csv',encoding='utf-8-sig')));print('数据行=',len(r),'去重月份=',len({x['月份'] for x in r if x.get('月份')}))"
   ```
   数据行 = 0 → 按 `SKILL.md`「失败分支 2」修复；仍失败则停下并报告用户，不进入第 4 步。

### 3.2 B · 邮箱 IMAP

> 抓取脚本 `salary_pipeline.py` 已随包提供；用环境变量传凭据，避免写进文件。

1. 在邮箱服务里开启 IMAP 并**生成授权码**（不是登录密码）。
2. 复制 `config.example.json` 为 `config.json`，改 `imap_server` / `imap_port`，并在 `sources` 里填发件人、主题关键词与 `save_subdir`。
3. 先**只读试跑**（连 IMAP 只列命中、不下载附件）：
   ```bash
   SALARY_EMAIL=<你的邮箱> SALARY_IMAP_AUTH_CODE=<授权码> python salary_pipeline.py fetch --dry-run > dryrun.log 2>&1
   cat dryrun.log
   ```
4. **量化核对命中**（四项全满足才算「确认命中无误」）：
   ```bash
   grep -c '^\[dry-run\]' dryrun.log       # 命中行数必须 ≥ 1
   grep -ciE 'error|traceback' dryrun.log  # 必须为 0
   ```
   逐条比对 `dryrun.log` 的发件人 / 主题 / 月份与 `config.json` 的 `sources` 关键词，必须一一对应、无预期外邮件。任一不满足 → 命中不符，按 `SKILL.md`「失败分支 3」修复；仍失败则停下并报告用户，不进入下一步。
5. 命中无误后先过决策点（CHECKPOINT ④）：

🔴 CHECKPOINT：等待用户明确回答/确认后方可继续

停留动作：把 `dryrun.log` 与量化结果贴给用户，问「命中无误，是否去掉 `--dry-run` 正式抓取？」；未确认就不再执行任何 `fetch`、不跑 `bill_parser.py`。

6. 用户明确确认后才正式抓取，再跑解析与看板：
   ```bash
   SALARY_EMAIL=<你的邮箱> SALARY_IMAP_AUTH_CODE=<授权码> python salary_pipeline.py fetch
   python bill_parser.py
   python dashboard.py
   ```
7. **验证**：`data/bills/<来源>/` 下出现附件，`data/bills_parsed.csv` 有数据行。

> ⚠️ 环境变量只报「是否设置」，不会把值写进任何日志或看板。请勿把真实凭据贴进聊天。

### 3.3 C · 其他数据源

系统只认两张 CSV，所以任何来源都可以接——**整理成 `bills_parsed.csv` 的 8 列**：

| 列 | 怎么填 |
|---|---|
| 来源 | 起一个展示名，如「支付宝」「房租」 |
| 月份 | `YYYY-MM` |
| 应还金额 | 该月支出金额 |
| 最低还款额 / 账单周期 / 用电量 | 不适用就留空 |
| 状态 | 填「已导入」等自定义文本 |
| 原始文件 | 导出文件名，便于回溯 |

触发条件：当且仅当来源本身是固定格式的 CSV 时，写一个小转换脚本输出这 8 列；否则按上表手工整理。两种情况都不改本包 Python，多个来源的 CSV 一律按第 4 步显式合并。

### 3.4 多个邮箱 / 多个工作区

**当前一次只连一个邮箱账号。** 多个邮箱用「多个工作区 + 环境变量凭据」分别抓，再合并：

```bash
# 邮箱 1
SALARY_DATA_DIR=<路径A> SALARY_EMAIL=<邮箱1> SALARY_IMAP_AUTH_CODE=<授权码1> \
  python salary_pipeline.py fetch
SALARY_DATA_DIR=<路径A> python bill_parser.py

# 邮箱 2
SALARY_DATA_DIR=<路径B> SALARY_EMAIL=<邮箱2> SALARY_IMAP_AUTH_CODE=<授权码2> \
  python salary_pipeline.py fetch
SALARY_DATA_DIR=<路径B> python bill_parser.py
```

- `SALARY_DATA_DIR` 的完整规则（优先级、`state.json` 跟随、隔离范围）见 `SKILL.md`「数据目录优先级」唯一一处，本文件不复述。
- 工资条若来自多个邮箱，把各自 `工资年度汇总.csv` 的「月度」行合并到主工作区同一张表（保留一个表头）。
- **前提（写死）**：`<路径A>` / `<路径B>` 是本步实际使用的两个工作区路径，必须原样带进第 4 步合并命令的输入列表；不要用 `glob('data*/...')` 之类前缀通配。

> 若确实需要「一个进程同时轮询多个邮箱账号」，属于抓取层改造，请明确告诉助手评估后再做——**当前版本不要声称支持**。

## 第 4 步 · 合并多份账单 CSV

**显式列出要合并的文件路径**（不用通配），保留第一份表头，其余只追加数据行：

```bash
python -c "import csv; ins=['data/bills_parsed.csv','<路径A>/bills_parsed.csv','<路径B>/bills_parsed.csv']; rows=[]; [rows.extend(list(csv.reader(open(f,encoding='utf-8-sig'))) if i==0 else list(csv.reader(open(f,encoding='utf-8-sig')))[1:]) for i,f in enumerate(ins)]; csv.writer(open('data/bills_parsed.csv','w',encoding='utf-8-sig',newline='')).writerows(rows); print('合并数据行=',len(rows)-1)"
```

前提：`ins` 只填 3.4 里实际产出 `bills_parsed.csv` 的工作区路径；单工作区时把 `ins` 收敛为 `['data/bills_parsed.csv']` 并跳过本步。原先用 `glob.glob('data*/bills_parsed.csv')` 会在工作区不以 `data` 开头时静默产出空表，已弃用。

❌ 打印「合并数据行 = 0」或输出只剩表头 → 按 `SKILL.md`「失败分支 4」修复；仍失败则停下并报告用户，不进入第 5 步。

合并后检查是否有同月同来源的重复记录（`bill_parser.py` 自带去重只作用于单次解析）。

## 第 5 步 · 生成、量化核对

```bash
python dashboard.py
```

打开 `data/收支统一看板_DEMO.html`，执行「核对数值一致」的量化命令（与 `SKILL.md`「量化核验」同一条）：

```bash
python -c "import csv,sys; r=list(csv.DictReader(open('data/bills_parsed.csv',encoding='utf-8-sig'))); m={x['月份'] for x in r if x.get('月份')}; h=open('data/收支统一看板_DEMO.html',encoding='utf-8').read(); miss=[x for x in m if x not in h]; print('去重月份数=',len(m),'缺失=',miss); sys.exit(1 if (not m or miss) else 0)"
```

量化判定：`bills_parsed.csv` 去重月份数 = 看板月度表行数（每个月份都出现在看板 HTML 中）；去重月份数 0、缺失月份非空、退出码非 0，任一即判「数值不一致」→ 按 `SKILL.md`「失败分支 5」处理，仍失败则停下并报告用户，不进入第 6 步。

另查外链：`grep -ciE '<script[^>]+src=|<link[^>]+href=' data/收支统一看板_DEMO.html` 必须为 0；5 个菜单面板、按月折叠按钮、内嵌 JSON 都在。

## 第 6 步 · 去掉水印

先展示第 5 步量化核对结果，再过决策点：

🔴 CHECKPOINT：等待用户明确回答/确认后方可继续

停留动作：问「数值一致，是否现在删除 `data/IS_DUMMY.txt` 并重生成？」；未确认就不执行 `rm`、不重跑 `python dashboard.py`。

用户明确确认后：

```bash
rm data/IS_DUMMY.txt
python dashboard.py
```

完成标志：`grep -c '演示数据' data/收支统一看板_DEMO.html` 为 0。

## 隐私核验（用户问「检查有没有把真实数据发出去」时执行）

不靠声明，按下面四条命令跑一遍，把实际输出交给用户：

```bash
# ① 列出全包会触发网络的代码位置
grep -rlniE "imaplib|smtplib|requests|urllib|urlopen|socket|IMAP4" --include="*.py" .
# ② 确认联网只发生在 salary_pipeline.py 的 IMAP 子命令分支
grep -nE 'def _imap_connect|def fetch_emails|def list_emails|add_parser|dry_run' salary_pipeline.py
# ③ 检查真实凭据 / 状态 / CSV 是否落在当前目录树（分发前必查）
find . -type f \( -name "config.json" -o -name "state.json" -o -name "*.csv" \) -print
# ④ 判断 data/ 是否仍是 dummy
test -f data/IS_DUMMY.txt && echo "dummy：安全，可分发" || echo "⚠️ 已含真实数据，禁止打包分发"
```

量化判定 / 核验结论：

- ① 命中只允许出现在 `salary_pipeline.py`（实测 1 个文件）；`setup_check.py` / `bill_parser.py` / `dashboard.py` / `generic_parser.py` / `app_config.py` / `safe_write.py` 出现任一命中即判异常。
- ② 中 `IMAP4_SSL` 连接只由 `_imap_connect()` 建立，且只被 `fetch` / `list` / `run` 等用户显式 IMAP 子命令调用；`--dry-run` 同样连 IMAP 只读列命中、不下载附件。**核验结论：仅用户显式执行 `salary_pipeline.py` 的 IMAP 子命令才联网；状态检测、账单解析、看板生成、CSV 合并全程本地、不上传。**
- ③ 出现 `config.json` 或 `state.json` 说明真实凭据 / 去重状态已落盘 → 不得打包分发，并提醒凭据只应走 `SALARY_EMAIL` / `SALARY_IMAP_AUTH_CODE` 环境变量。
- ④ 输出「已含真实数据」时，禁止把 `data/` 或 `data/收支统一看板_DEMO.html` 复制进共享位置、转发或上传。

把四条实际输出贴给用户即为「可验证结论」；任一条不满足 → 停下并报告用户，不继续交付。

## 红线与常见问答

| 问 | 答 |
|---|---|
| 有没有把真实数据发出去？ | 执行上面「隐私核验」四条命令，按量化判定逐条给结论，不靠口头声明 |
| 会不会自动上传我的数据？ | 同「隐私核验」；结论以四条命令的实际输出为准，本表不重复声明 |
| 别人能看到我的看板吗？ | 本包内只有 dummy 数据；真实数据留在你自己的 `data/`，不要打包转发 |
| 多个邮箱会不会串数据？ | 用 `SALARY_DATA_DIR` 分工作区，state 与产物都隔离；规则见 `SKILL.md`「数据目录优先级」 |
| 想换一套数据？ | 设置 `SALARY_DATA_DIR` 指向另一目录，不用改代码；规则见 `SKILL.md`「数据目录优先级」 |
| 接了新来源但看板没变化？ | 检查 `save_subdir` 末段是否与目录名一致、正则是否匹配、是否重跑 `python bill_parser.py` |
| 账单金额为空 / 状态「未匹配到金额」 | 正则与账单文字不符，改 `profiles/sources.json` 的 `patterns`（`references/配置指南.md`） |
| 月份全是 `unknown` | 文件名缺 `YYYY-MM`，或配置 `period` 正则 |
| 「账单目录不存在」 | `data/bills/` 未创建，或 `SALARY_DATA_DIR` 指错（规则见 `SKILL.md`「数据目录优先级」） |
| 看板是空的 | 两张 CSV 都不存在或表头不符，核对 `references/数据格式.md` |
| 水印删不掉？ | 删除的是 `data/IS_DUMMY.txt`，删完要重跑 `python dashboard.py` |
| 需要装 WorkBuddy 吗？ | 不需要。引导是给 Agent 用的；所有脚本都能命令行直接跑 |
